# Host Watch Together for free

**Setup:** the app runs on **Render** (free web service) and the data lives in **MongoDB Atlas** (free database). Total cost: 0. Time: about 20 minutes.

Why not Vercel (the old setup)? Vercel runs code in short-lived functions, so the live connection that keeps videos and chat in sync (Socket.IO) cannot stay open there. Render runs a normal, always-connected server.

## What "free" means here

| | Render free web service | MongoDB Atlas free cluster |
|---|---|---|
| Limit | 750 hours per month (one app running all month fits) | 512 MB of data |
| Catch | Sleeps after 15 minutes with no visitors; the next visit takes about 1 minute to wake it | Slower than paid clusters; no backups |
| Card | Not needed | Not needed |

Fine for friends and testing. For a site that must answer instantly at any time, use a paid plan (Render's cheapest paid web service does not sleep).

## 1. Put the code on GitHub

The code must be pushed to `github.com/mel-mehdi/watch_together` (Render deploys from there):

```bash
git add -A
git commit -m "Prepare for Render + MongoDB Atlas"
git push origin main
```

Your `.env` file is ignored by git and is never uploaded. Keep it that way.

## 2. Create the free database (MongoDB Atlas)

1. Sign up at https://www.mongodb.com/cloud/atlas/register.
2. **Create a cluster** → choose **Free** → pick a region close to your users (for example Frankfurt or Paris) → **Create**.
3. **Database user:** Atlas asks you to create one. Choose a username, click *Autogenerate password*, and save both somewhere safe (a password manager).
4. **Network access:** go to *Security → Network Access → Add IP Address → Allow access from anywhere* (`0.0.0.0/0`). Render's free plan has no fixed address, so this is needed; the database password still protects it.
5. **Connection string:** *Database → Connect → Drivers*. Copy the string; it looks like
   `mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority`
6. Put your user and password in it, and add the database name `watch-together` after `.net/`:
   `mongodb+srv://myuser:mypassword@cluster0.xxxxx.mongodb.net/watch-together?retryWrites=true&w=majority`

   If your password has symbols like `@`, `:` or `/`, regenerate one without them (or URL-encode it).

## 3. Deploy the app (Render)

1. Sign up at https://render.com with **GitHub**, and allow it to see the `watch_together` repository.
2. **New → Blueprint** → choose `watch_together`. Render reads `render.yaml` from the repository.
3. Render asks for **MONGO_URI**: paste the connection string from step 2.6.
   `JWT_SECRET` and `SESSION_SECRET` are generated by Render automatically.
4. Click **Apply** and wait for the build (2–4 minutes).
5. Your site is at `https://watch-together-xxxx.onrender.com` (shown in the Render dashboard).
   Check it: `https://watch-together-xxxx.onrender.com/health` should say `"database": "connected"`.

From now on, every `git push` to `main` redeploys the site automatically.

## 4. Check it works

Open the site in two different browsers (or one normal and one private window), create an account in each, create a room in one and join it from the other with the code. Chat, reactions and play/pause should sync.

## Troubleshooting

| Problem | Fix |
|---|---|
| Build fails | Render dashboard → the service → **Logs**. |
| `/health` says `"database": "disconnected"` | Wrong `MONGO_URI` (user, password or database name), or Network Access in Atlas does not allow `0.0.0.0/0`. Fix it in Render → **Environment**, then **Manual Deploy**. |
| Log says `Missing required environment variable(s)` | Render → **Environment**: add `JWT_SECRET` and `SESSION_SECRET` (any long random text). |
| First visit is slow | Normal on the free plan: the app was asleep. |

## Optional settings

Add these in Render → **Environment** only if you use the feature:

| Variable | For |
|---|---|
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_CALLBACK_URL` | "Sign in with Google". The callback is `https://<your-site>.onrender.com/api/auth/google/callback`, and the same address must be added in Google Cloud Console. |
| `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USER`, `EMAIL_PASS`, `FROM_EMAIL` | Password-reset emails. With Gmail: `EMAIL_HOST=smtp.gmail.com` and an App Password as `EMAIL_PASS`. |
